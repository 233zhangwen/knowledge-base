## 4. 三件必须单独说的事

### 4.1 c19 的 `expectChunks[0]` 本来就标错了

c19 问的是「年假 + 婚假合计最多多少天」（答案 29 = 17 + 12），但它的两个期望块是：

| | 改前标的块 | 那个块讲什么 | 应该标什么 |
|---|---|---|---|
| expect[0] | C#1 | **考勤 / 迟到公示** | 年假条款 |
| expect[1] | C#2 | 年假 + 婚假 | 婚假条款（跨块） |

也就是说：**这条题从建库起就一直带着一个无关的期望块**，而两道校验都放行了 ——
`--check` 只验指纹，`check:cases` 只看"有没有任何一个期望块含关键词"（#2 含 `17`，于是通过）。
这也是 `check:cases` 只能在报告里写"可疑清单、不是错误清单"的原因。

重锚时按内容把它改成「年假块 + 婚假块」。这次改的是**标注**，不是判据。

### 4.2 c16 的判据漏了一种写法，改的是判据

第 1 跑 c16 判错，但答案是对的：

> 经查实的举报，公司按挽回损失的**百分之五**给予奖励，单笔奖励上限为 **20000 元**

判据是 `answerMustContain: ["5%", "20000"]`，模型写的是「百分之五」。
`answer-match.mjs` 的设计里明确写了「**不做中文数字转换**，遇到这类题把两种写法都写进 `answerAnyOf`」，
所以按既定规则改判据：

```diff
- "answerMustContain": ["5%", "20000"]
+ "answerMustContain": ["20000"],
+ "answerAnyOf": [["5%", "百分之五"]]
```

这不是"为了让分数好看放松判据"：`20000` 仍然必须出现，`5%` 仍是必须命中，
只是承认「百分之五」和「5%」是同一个事实的两种写法。
W16 已经记过一次同类误判（`不可以` vs `禁止`、`8周` vs `8 周`），方向都是**把对的判成错的**。

### 4.3 v04 是真退步：块被稀释，掉出召回

v04 问「未休年假折算工资的倍数标准」。答案句在「十一、离职与交接」的结算段：
「未休年假按日均工资的 **2 倍**折算，最多折算 10 天」。

重切片后这块从 `#8`（378 字，只含 交接+结算+附则）变成 `#7`（460 字，前面多了「辞职提前 30 天」那一段）。
同一句话，同一个 embedding 模型，**余弦相似度掉了 9.4%**：

| | 块长 | 与问题的余弦 |
|---|---|---|
| 旧 #8 | 378 字 | **0.5818** |
| 新 #7 | 460 字 | **0.5271** |

粗排前 10（`recall`）里已经没有这块了 —— 不是 rerank 压下去的，是**根本没进候选**。
所以模型的回答是「文档中没有相关内容」，而事实上文档里明明白白写着。

**为什么不在本周修**：修它只能动切片策略（比如按小节强制断块、或让块长随内容自适应），
而那会让 52 条全部重锚一次 —— 那是独立的一周，而且要重新论证"改进还是又一次抽签"。
本周的定位是"换文档 + 把重锚做成可重复的路"，不是"顺便调优检索"。

**它证明了什么**：500 字定长贪心切片是**抽签**。同内容换一次边界，有的题变容易，有的题变难。
以前这个抽签结果被当成"系统能力"，现在有了一个具体的反例可以引用。

## 5. 复现

```bash
# 1. 建库（6 篇全部在仓库里，不再需要"某份只存在于线上库的文档"）
npm run seed:kb                 # 默认写「知识库C」；--only=C- 只灌一篇；--dry --show 只看切片
npm run backfill:meta           # 抽生效日期 / 废止关系

# 2. 校验标注（文档一改，这两步必跑）
node scripts/eval.mjs --check   # 结构：指纹是否仍是块首
npm run check:cases             # 语义：块里到底有没有答案（给的是可疑清单）

# 3. 全量评测
npm run eval:agent              # 52 条，答案层 + 检索次数 + token + 证据覆盖
```

文档再变动时：

```bash
npm run realign:cases -- --rename="旧标题=新标题" [--accept=id:where@文档片段:旧>新 ...] --write
```

它会打印 85 处锚点各自的去向（未变 / 移动 / 需人工），**需要人工的一律不猜**，
不允许写回，直到用 `--accept` 明确指定。
